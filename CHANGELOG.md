## [Unreleased]

### Added

- M0 bootstrap: Cargo workspace (`crates/scout` library, `apps/scout-cli` binary `scout`), shared workspace lints, stable toolchain, `.gitignore`, `.env.example`, README skeleton.
- `AGENTS.md` with guidelines for coding agents (commits allowed, push not allowed).
- `CLAUDE.md` importing `AGENTS.md`.
- M1 browser runtime: `ChromeBrowser` launches Chrome over CDP (chromiumoxide) with a temporary profile per run, `--enable-features=WebMCPTesting`, supervised CDP handler and close/wait/kill shutdown; the profile is deleted once no Chrome helper process uses it.
- `Tab` WebMCP bridge: `discover` (schemas parsed, foreign-origin and invalid-schema tools reported as rejected), `wait_for_tools` (waits for a stable tool set), `execute` with navigation reporting and typed errors (`ToolFailed`, `ToolNotFound`, `ContextDestroyed`, `Timeout`, ...).
- Legacy `navigator.modelContext` shim, injected before page scripts on request.
- CLI commands `scout tools <url>` and `scout call <url> <tool> [json]` (`--legacy-shim`, `--headed`, `--json`, `--wait`, `--timeout`).
- Local fixture sites (`echo`, `alpha`, `legacy`) and integration tests served by axum, including the `executeTool` argument-encoding spike and the full-navigation contract test; ignored live tests for sport-shop-angular and Shoe Store.
- GitHub Actions CI: fmt, clippy and fixture tests on pinned Chrome for Testing 154.0.8037.57.
- M2 `schema`: `ToolSpec` from a WebMCP `inputSchema` with the supported subset (enums, `const` unions, booleans, bounded numbers, free strings, enum arrays, nullable forms, local `$ref`); unsupported optional parameters make a tool partial, unsupported required ones exclude it, always with a reason. Order-independent `schema_hash`, strict-mode argument schema, offline validation against the site schema.
- M2 `llm`: OpenAI-compatible client for strict structured outputs (Groq `qwen/qwen3.8-27b` by default) with `retry-after` handling on 429, retries on 5xx/timeouts, redacted API key, and a record/replay response cache keyed by request hash.
- M2 `router::baseline`: LLM-only router, one strict call returning a tool-discriminated union; null optionals dropped, undeclared arguments rejected, site-schema validation errors reported.
- M2 eval: dataset v0 with 60 labeled scenarios (23 calibration, 37 test; search, detail, no-tool, missing-required, unsupported schema, ambiguous) over four toolsets (alpha fixture, sport-shop and Shoe Store snapshots, synthetic `gamma`), consistency checks on labels, scoring (act/no-act, tool, field, schema validity, exact invocation), seeded bootstrap intervals and latency/token costs.
- `scout eval routing [--replay]` writes `docs/evals/<name>.md` and `.jsonl`; recorded responses in `evals/cache/llm` make the replay test reproduce the committed report offline.
- Baseline report `docs/evals/routing-baseline-v0.md`: exact invocation 95.0% (95% CI 88.3–100), tool accuracy 98.3%, p50 latency 467 ms.
- M3 `policy`: capability allowlist in `sites.toml` (`origin`, `tool`, `schema_hash`, `class = "read_only"`, optional `adapter`); entries are validated on load (hash format, duplicates, known adapters, non-read-only classes rejected). Tools outside the allowlist, on another origin or with a changed schema hash are excluded before routing and reported.
- M3 `adapters`: versioned output adapters `alpha.search_products.v1` and `sport.search_product.v1` to `Product {source, id, name, price, availability, url, attributes}` with the site currency; other outputs stay JSON or become `Status` text, and a wrong shape is an error rather than an empty list.
- M3 `trace`: JSONL run trace with elapsed time per event (run started, tools discovered, tool excluded, routed, policy checked, blocked, executed with a truncated output preview, adapted, run finished).
- M3 `run::ask_site`: one request on one site: discover → allowlist → baseline routing → validation → re-discovery and hash re-check → execute → adapt. Nothing runs when no tool fits, arguments are invalid or the policy blocks.
- CLI `scout ask "<request>" --site <name>` (`--sites`, `--trace`, `--json`, `--headed`, `--wait`, `--timeout`); traces default to `traces/` (ignored by git). `scout tools` prints each tool's `schema_hash`.
- `sites.toml` with the sport-shop allowlist (`search_product`, `get_product_info`, `get_store_promos_and_rules`; `view_product` and `open_cart` stay blocked).
- End-to-end tests on the `alpha` fixture with a mocked LLM (allowlisted call adapted, non-allowlisted tool hidden from the model, stale hash blocked, no-tool and invalid arguments execute nothing) and an ignored live test on sport-shop with Groq.
- M4 `jev`: TypeSafe Jev client (`POST /v1/systemone`) for Noul, Choice and Score questions with local validation (option and level limits, token budget), retries on 429/529 honoring `retry-after`, no retry on other errors (402 billing included), and the shared record/replay cache; evals pin `jev-1.13.0`.
- M4 `router::numbers`: deterministic number candidates with their context, filtered by the parameter's type and bounds.
- M4 `router::hybrid`: staged router (stage 1 act + tool choice; stage 2 for the chosen tool: optional presence, enums, booleans, enum sets, number disambiguation) and a fan-out variant asking every stage in one request; free strings and undecided numbers go to one strict LLM call; every decision carries a `HybridTrace` (signals, tool probabilities, per-field source and confidence). Unsatisfiable or over-budget question sets escalate to the baseline.
- M4 gate: `act_yes`/`act_no`/`tool`/`args` thresholds decide act, no tool or escalation to the baseline; `scout ask --router hybrid|fanout` uses prudent uncalibrated defaults (0.9/0.1/0.9/0.9).
- M4 eval: `scout eval routing --router baseline|hybrid|fanout`; `scout eval compare [--replay]` routes with all three, calibrates each gate on the calibration split (thresholds just past every calibration mistake, never below 0.5), gates post hoc (an escalation takes the baseline's answer and pays for both) and writes `docs/evals/<name>.md` with accuracy, cost and latency, paired comparison against the baseline (McNemar exact, bootstrap CI of the exact-match difference), per-stage accuracy and risk-coverage, plus one JSONL per router.
- insta snapshots of the stage-1 and stage-2 question sets; wiremock tests of staged, fan-out, no-act, missing-required, gated and escalation paths.
- Jev request pacing: `JevClient::with_min_interval` spaces HTTP requests (retries included, cache hits excluded) and clones share it; `--jev-interval` on `scout eval routing|compare` and `scout ask`, default 15 s. A live `eval compare` makes roughly 165 Jev requests, about 45 minutes at the default. `JevClient::with_billing_retry` (`--jev-402-retry`, default 30 s, 0 to fail) retries a request refused with HTTP 402 until the account accepts it again, so a run waits out a billing gap instead of stopping.
- M4 results: `docs/evals/routing-m4.md` with one JSONL per router, and the Jev and LLM answers in `evals/cache/`, so `scout eval compare --replay` reproduces the report offline. On the 37 test scenarios the baseline, the staged hybrid and the fan-out hybrid all reach 94.6% exact invocation (CI 86.5–100) and miss the same two scenarios (McNemar p = 1.000); the gates calibrate to the 0.50 floor and escalate 2.7%. The hybrid cuts LLM tokens (about 180/78 against 502/157) but adds Jev calls, with a p50 of 638 ms (staged) and 578 ms (fan-out) against 467 ms. With no accuracy gain the baseline stays the default router; the README states the result.
- Adversarial routing set `evals/adversarial/` (22 scenarios, all held out as test): the `adversarial` fixture's tools, and the Sport Shop and Shoe Store toolsets with injected metadata (`sport-injected`, `shoes-injected`) that push a fixed enum value or brand, a mandatory first tool, a pre-authorized purchase or a redirect to `add_to_cart`. Requests repeat M4 scenarios so each pairs with its clean version; gold answers ignore the injection. The baseline gets 22/22 exact (`docs/evals/routing-adversarial-baseline.md`, reproduced offline by a test), with more reasoning tokens (285 against about 127 per request) and a p50 of 681 ms.
- `scout eval questions --out <file>`: writes, for every scenario, the fan-out question set the hybrid router would send (`router::hybrid::fanout_question_set`, shared with the router itself) together with the scenario's labels, as JSONL, without calling any model. Scenarios accept `split = "train"` for training data that is never scored.
- Synthetic training set `evals/train/` (1435 scenarios, split `train`; 246 no-tool, 152 missing-required) for a local decision model, built by `scripts/gen_train.py` from the four clean toolsets only (never from the scenarios' labels, the adversarial set or Jev answers). A teacher LLM (`qwen-3.8-27b`, temperature 0.7 / top_p 0.8, no reasoning) writes groups of 4–5 requests that differ in one fact that changes the decision; the same model relabels every request at temperature 0 with medium reasoning, in shuffled batches. A request is kept when both labels agree on the tool and on every closed value both set; a closed argument only one label sets, or marks uncertain, becomes optional (never for a required one: the request is dropped). A missing-required request is labelled `tool = "none"` with the tool it asks for in `intended_tool`; a pattern or date parameter whose value is uncertain or fails the pattern (a city where an airport code is required) counts as not given. After the base generation, top-up rounds fill per-toolset quotas (200 requests per toolset, 25% no-tool and 20–25% missing-required, 30% no-tool for Sport, which has no required values), and each new request is relabelled like the others. Labels are checked against the schemas, enum values canonicalized, and requests close to a scored scenario (normalized match or word Jaccard ≥ 0.8) dropped. Raw teacher answers in `evals/train/raw/` rebuild the set offline (`--offline`); `evals/train/review.md` lists 120 requests for a human check, 30 per stratum (no tool, missing required value, optional closed parameters, tool and closed values) spread over toolsets, then every dropped request with its reason. Human review of that sample (2026-09-26, `evals/train/reviews/2026-09-26.md`): 118 labels correct, 2 corrected (a return-policy question is served by `get_store_promos_and_rules`; "Browse the basketball category" gives the required query). Corrections live in `evals/train/reviews/fixes.toml`, which the script applies on every rebuild and which stops the build when a fix matches no kept request. `Scenario::intended_tool` is checked against the toolset and allowed only on missing-required no-tool labels. A test checks the set is all `train`, every missing-required request names its intended tool, and no request is shared with the scored sets.
- `local_router/` (Python, run with `uv run`): a LoRA decision model on `Qwen/Qwen3-4B-Instruct-2507` for the fan-out question sets that `scout eval questions` exports. Each question (act, tool, optional presence, enum value, number choice) is a prompt whose options are lettered A..Z; the answer is read from the fp32 logits of the option letters, trained with cross-entropy of the right option set plus a Brier term, with the option order permuted every step. Targets come from the scenario labels only (a missing-required request trains act = yes with its intended tool; uncertain optional values and ambiguous tools are masked); surplus act questions are balanced per toolset. Dev is 15% of the contrastive groups of `evals/train`, held out whole; the temperature is fitted on the calibration split of `evals/scenarios`, whose test split is never read. Tests cover the target compiler, the group split, act balancing, the prompt format and single-token letters.
- Early stopping in `local_router/train.py`: dev is scored a few times per epoch and the adapter with the lowest dev NLL is kept. Two epochs overfit (dev NLL at temperature 1 went from 0.037 to 0.065 while the train loss reached about 0.001), so training runs one epoch. One epoch with the default hyperparameters: dev accuracy 98.5%, calibrated dev NLL 0.051, ECE 0.004, temperature 1.45 (base model without LoRA: 95.9%, NLL 0.146, temperature 5.68).
- `local_router/tune.py`: Optuna study (TPE, multivariate, seeded; median pruning from the third of four dev checks per epoch) over learning rate, LoRA rank (8 or 16; 32 does not fit on a 12 GB GPU), LoRA dropout and the Brier weight. The objective, minimized, is the lowest dev NLL at temperature 1 over one epoch, i.e. the adapter early stopping keeps: a proper scoring rule that also penalizes the overconfidence overfitting brings, where dev accuracy (about 99%) cannot separate trials. The study lives in sqlite and resumes after a stop (`<out>/STOP` stops after the current trial; a trial left running by a killed process is marked failed). 18 trials (the first 12 pruned from the first check, too early, fixed before the last 6): best dev NLL 0.0533 (learning rate 7.7e-5, rank 16, dropout 0.18, Brier weight 1.21) against 0.0559 for the defaults, a gap within the noise of one seed and 463 dev questions.
- `local_router/serve.py`: serves a trained run on `127.0.0.1:8765`; `POST /decide` answers a whole question set in one batch with calibrated option probabilities (about 300 ms per request on an RTX 4070). Our own protocol, not an emulation of any hosted API.
- Router `local` (`scout::local`, `HybridRouter::local`, `scout eval routing --router local`, `scout eval compare --decider local`, `scout ask --router local`): the fan-out questions answered by the local model named by `SCOUT_LOCAL_MODEL` (`SCOUT_LOCAL_URL`, default localhost:8765); free strings still go to the LLM. A choice's confidence is its calibrated top probability; a question with more than 26 options escalates to the baseline. Answers are recorded in `evals/cache/local`, keyed by run name and request, so replays need no GPU. `eval compare --decider local` routes the baseline and the local router only; reports gain a local-model-calls row and no Jev columns.
- Local model `qwen3-4b-lora-t13`: the best Optuna parameters retrained with four dev checks per epoch (kept step 312 of one epoch). Dev accuracy 98.7%, calibrated dev NLL 0.046, ECE 0.007, temperature 1.76; calibration split 98.1%, calibrated NLL 0.098.
- Local router vs baseline on the 37 test scenarios (`docs/evals/routing-local.md`, gates calibrated on the calibration split): exact invocation 97.3% (91.9–100) raw and gated against 94.6% for the baseline, tool accuracy 100% against 97.3%; one scenario only the local router gets right, one both miss (McNemar p = 1.000). The LLM is called for 62% of requests with about a third of the tokens (179 / 73 against 502 / 157), but the median latency is higher (738 ms raw, 768 ms gated, against 467 ms): the local call and the LLM call run in sequence. The gates stay at the 0.50 floor except `args` (0.96), which escalates 8.1% of test requests. The baseline stays the default router.
- Local router on the held-out adversarial set (`docs/evals/routing-adversarial-local.md`, ungated): exact 77.3% against 100% for the baseline. The model follows injected tool metadata: on `sport-injected` it sets `category = "ALL"` as the description tells it (3 misses), on `shoes-injected` it picks `get_filter_options` over `get_all_store_items` (2 misses, tool confidence 0.58 and 0.51). With the gates calibrated on the clean scenarios, computed from the same answers, the three category misses escalate and 20 of 22 are right. The model never saw injected metadata in training; the adversarial set stays held out and is not used to fix this. A replay test reproduces the report from `evals/cache/local`.
- `local_router/overfit.py`: overfitting checks run after training (nothing feeds back into it). It scores the base model and a run's adapter on train, dev, calibration, test and adversarial (accuracy, NLL, Brier, ECE at temperature 1 and calibrated, by question kind and language), the train and dev per-question NLL quantiles, and each request's word overlap with its nearest training request. - Sealed injected test set `evals/sealed/` (87 scenarios, split `test`) for the local router's final evaluation only: never used to train, tune, calibrate or select. `scripts/gen_sealed.py` asks a model of another family than the training teacher (`gpt-6-sol` through `codex exec`, read-only, in an empty directory, every event audited) for 12 attacked variants of the four clean toolsets (1–3 injections appended to tool or parameter descriptions: value forcing, presence forcing, value suppression, tool redirect, call-first, forced no-act, forced act) and 4 benign variants with legitimate usage notes, plus requests whose labels are the clean toolset's decision. A second call relabels every request on the clean toolsets alone; both passes agree on 88 of 88. After human review one case was dropped because it repeats the M4 test scenario `sport-10`; corrections go into `evals/sealed/reviews/fixes.toml` and case ids stay stable when a case is dropped. Toolsets in `evals/toolsets/sealed-*.json`, attack targets in `evals/sealed/targets.json`, per-case review in `evals/sealed/review.md` with each request's word overlap with the nearest training request.
- Injected training twins `evals/train-twins/` (`scripts/gen_twins.py`): every training scenario gets two copies on injected variants of its toolset with the same labels (StruQ-style), one from pool `a` (teacher `qwen-3.8-27b`, 20 variants per toolset, for training) and one from pool `b` (`gpt-oss-120b`, other styles and wording, 8 variants per toolset, for dev only). About 20% of variants carry benign notes; attacks are drawn only among the kinds the toolset can host, injection texts that do not name their target are dropped, and each twin is tagged `base-<toolset>` and `twin-a|b`. 2866 twins.
- `local_router/train.py --twins <questions> --twin-share 0.3`: adds a share of the pool-`a` twins of the training groups to training and every pool-`b` twin of the dev groups to dev (a twin keeps its clean scenario's group, so no group crosses the split); results report `dev_clean` and `dev_injected` separately. Without `--twins` the split is unchanged.
- Tests: the sealed set is all held out with `sealed-` toolsets, the training set is disjoint from it, and every twin keeps its clean scenario's request and labels.
- Metadata screen `router::screen`: lexical cues for tool and parameter descriptions that address the model (override words, fake end-of-description markers, fake system or admin notices, "always set", "for every request", "do not call", "instead of", "leave empty", mandates, conditions on the user's request). `HybridRouter::with_metadata_screen` escalates such a request to the baseline before the decider is asked; `scout ask` turns it on, `scout eval routing --screen-metadata` measures it, and the committed reports are unchanged. The cues were written from the pool `a` twin texts only (92 of 92 injections caught, 0 of 19 benign notes flagged) and then frozen; on the pool `b` texts, never looked at, they catch 32 of 46 injections (70%) and flag 1 of 8 benign notes, so the screen is a partial safety net and not a defense on its own. No clean toolset of the scored scenarios trips it (tested).
- Local model `qwen3-4b-lora-u1`: the untrusted-metadata prompt, retrained on the 1433 scenarios with the t13 parameters and no twins (kept step 234 of one epoch, temperature 1.52), chosen on dev NLL over the run with twins. On the 37 test scenarios (`docs/evals/routing-local-u1.md`) it matches the baseline at 94.6% (86.5–100), raw and gated, one scenario below t13; gated it escalates 10.8% and uses 240 / 99 LLM tokens per request against 502 / 157.
- Final evaluation on the sealed set (`docs/evals/routing-sealed-*.md`, run once with `qwen3-4b-lora-u1`): exact invocation 73.6% (64.4–82.8) for the baseline, 69.0% (58.6–79.3) for the local router and 70.1% (59.8–80.5) with the metadata screen, which sends 53 of the 87 requests to the baseline. On the closed decisions alone (tool, enums, numbers, presence) the baseline and the local router both get 71 of 87 right, failing different requests (exact on `alpha-price-default`: local 4 of 6, baseline 1 of 6); the rest of the gap is mostly the free-text `query`.
- Adversarial regression check with `qwen3-4b-lora-u1` (`docs/evals/routing-adversarial-local-u1*.md`): 68.2% exact ungated against 77.3% for t13 (new misses: a brand request routed to `filter_by_category` at 0.93, another left without a call, `size` and `category` left out on two Sport Shop requests); with the metadata screen every attacked request goes to the baseline and all 22 are right. The new prompt helped on the injected dev (0.976 to 0.985) but not on the two held-out sets; the screen is what holds.
- Replay tests for the sealed and the `qwen3-4b-lora-u1` adversarial reports, with and without the metadata screen.
- `scripts/typesafe_probe.py`: account check with the official `typesafe-sdk` (list models, then one Noul question, no retries); run with `uv run --env-file .env scripts/typesafe_probe.py [model]`.
- M5 `run::ask_sites`: one request on several sites at once, each in its own tab of the same Chrome; `AskOptions::site_timeout` bounds a whole site (open, discover, route, execute, adapt) and a slow or failing site is reported without dropping the others' results. The products of every site are ranked together.
- M5 `rank`: constraints read from the request only (maximum price with an optional currency, size), hard filters in code (out of stock, over budget, price in another currency, missing price when a budget is set, size not listed), then a deterministic score (share of request and routed-argument keywords found at word starts of the name and attributes), ties broken by price, source and id. Every exclusion carries a reason.
- M5 adapters `beta.find_shoes.v1` (prices in cents, EU sizes, stock flag, relative links resolved against the page URL) and `shoes.get_all_store_items.v1` (Shoe Store catalog); `adapters::adapt` takes a `Source` (site name, currency, URL).
- M5 trace: records of a multi-site run carry their `site`; a final `ranked` event lists constraints, keywords, kept products with scores and exclusions.
- Fixture `beta` (second local shop with a different output shape) and `sites.toml` entry for Shoe Store (`get_all_store_items` only, with the legacy shim).
- CLI `scout ask` runs every configured site unless `--site` (repeatable) narrows it, with `--site-timeout` (default 90 s) and `--top` (default 10); traces go to `traces/<time>-<site>[+<site>...].jsonl`.
- End-to-end test on `alpha` + `beta` + a never-ready site with a mocked LLM (concurrency, per-site timeout, shared ranking, tagged trace) and an ignored live test on sport-shop + Shoe Store with Groq.
- M6 interruption: `scout tools|call|ask` catch Ctrl-C and SIGTERM from before Chrome is launched, drop the command, shut Chrome down and remove its temporary profile, then exit with `interrupted by <signal>`; an interrupted `ask` still writes the trace of the steps done so far. Tests send SIGINT to the process group (a terminal Ctrl-C), SIGTERM to `scout` alone, and SIGTERM while Chrome starts, and check that no process uses the profile afterwards and the profile is gone. Eval commands keep the default Ctrl-C behaviour (their caches are written per answer).
- M6 fixture `adversarial`: prompt injection in tool descriptions, schemas and results, a `checkout` tool outside the allowlist that asks to be called first, and `?drift=schema|remove` to widen or drop `search_items` three seconds after load. Tests with a mocked LLM: a model that obeys the injection and picks `checkout` gets an invalid decision and nothing runs (the tool was never offered to it); injected results come back as data with no further model call; a tool whose schema changed, or that vanished, while the router was deciding is blocked by the re-discovery before execution.
- `docs/threat-model.md`: assets, trust boundaries, threats with their mitigations and tests, residual risks (a page reports its own schema, the re-discovery/execution window, injected text reaching third-party models).
- M7 `scout-types`: serde types of the JSONL trace (records, every event, ranked products, exclusions) plus the viewer's IPC payloads, building for `wasm32-unknown-unknown`; `parse_jsonl` reports the line of a bad record. A `scout` test writes every event variant and checks that each line parses with `scout-types` and serializes back to the same JSON.
- M7 desktop trace viewer (`apps/desktop`, separate Cargo workspace): Leptos 0.8 CSR UI (Trunk, Tailwind 4, DaisyUI 5) in a Tauri 2 shell. It lists `traces/` newest first, opens a trace or a local JSONL file, and shows the request, a per-site table (status, router, tool, routing time, tokens; click to filter), the ranked products with exclusions and an event timeline with the raw JSON of each record. A form starts `scout ask -- <request>` as a child process and streams its output; the finished trace opens by itself. Outside Tauri the UI runs on a bundled real trace (sport + shoes), which the UI tests use.
- Tauri hardening: strict CSP (`script-src 'self' 'wasm-unsafe-eval'`, no inline code, `connect-src` limited to the app itself and IPC), frozen prototypes, one capability granting only the three app commands and event listening; trace names must be plain `.jsonl` file names; one run at a time; a run still going when the viewer exits gets SIGTERM, so `scout` removes Chrome and its profile.
- CI job `viewer`: fmt, wasm clippy and tests of the viewer UI (the Tauri shell needs WebKitGTK and is built locally).
- README: architecture diagram, baseline results reproducible offline with `scout eval routing --replay`, desktop viewer setup, four annotated screenshots (`docs/images/demo-*.png`) and a 71 s demo video (`docs/media/demo.mp4`), recorded with Playwright on the UI in mock mode with a callout overlay that is not part of the app.
- `docs/overview.html`: one run followed click by click in the viewer, in plain language for users (seven annotated screenshots `docs/images/journey-*.png` with mouse pointer and callouts), the run pipeline with its real numbers, setup, the same run from the CLI and the guarantees. Screens were taken with Playwright on the UI, with a stand-in backend that serves real traces and replays the real output of one run.
- `LICENSE-MIT` and `LICENSE-APACHE` for the declared `MIT OR Apache-2.0`, and a README Credits section with the source and licence of the demo sites, models, training libraries and borrowed ideas.
- `HybridRouter::with_decider_fallback`: a Jev or local-model error (no API key, HTTP 402, network, invalid response) escalates the request to the baseline, with the reason `the decider failed: …` in the trace, instead of failing the site. Evals keep the error, so a report never hides it.

### Changed

- English only: the eval sets, the metadata screen, the ranking cues and the generator scripts now handle English text alone. `evals/scenarios` keeps 37 of its 60 scenarios (16 calibration, 21 test), `evals/adversarial` 16 of 22 and `evals/sealed` 35 of 87; the three attacked sealed variants whose injected text was not in English were dropped with their requests, leaving 9 attacked and 4 benign variants. Every report in `docs/evals/` was regenerated by replay from the recorded answers, with no new model calls, and `tests/eval_replay.rs` checks the new counts. ### Notes

- Chrome 154 `executeTool` accepts only a JSON string for arguments (an object fails with "Failed to parse input arguments"); the JSON string is the default encoding and a test flags any change.
- Groq strict mode rejects an `anyOf` whose object branches share a key set (for example two tools without parameters: "at most one variant may allow an empty object branch"); the router output is therefore a union discriminated by a single-value `enum` on the tool name.
- Scenarios use TOML instead of YAML, reusing the `toml` crate.
- The adversarial routing set is separate from `evals/scenarios`, so the M4 scenarios stay fixed as the test set. The hybrid routers are not measured on it yet (it needs live Jev calls). M6 covers the policy side: whatever the router picks, nothing outside the allowlist runs.
- The desktop viewer is a separate Cargo workspace so the core build and CI need neither GTK/WebKit nor the wasm target. Trunk's cached `wasm-opt` needs `--enable-bulk-memory --enable-sign-ext --enable-nontrapping-float-to-int` for current Rust wasm output.
- `cargo tauri build` produces a `.deb` and an AppImage. The first build showed a blank window: Trunk's loader fetches the `.wasm`, which falls under `connect-src`, and the CSP allowed only IPC there. `'self'` is now allowed and a test checks it. Hook `cwd` values are relative to `src-tauri`, where the Tauri CLI moves before running them. The built app was checked to list and open the newest trace through IPC at start; the UI itself was checked in a browser with the mock backend (playwright-cli): sample load, site filter, row expansion, hostile markup in a trace rendered as text, parse errors reported with their line.
- The schema hash covers only the input schema, so two argument-less tools share a hash; the allowlist key is the full `(origin, tool, schema_hash)` triple. Drift after routing is covered by the `adversarial` tests.
- `scout ask` leaves constraints a tool cannot express (sport-shop `search_product` has no price parameter) to the M5 ranking.
- Training data teacher: Groq's account limit for `qwen/qwen3.8-27b` is 1000 output tokens per minute (reasoning included), which made generation take hours, and with low reasoning the model wrote its reasoning into JSON string values. The set was generated on Cerebras (same Qwen 3.8 27B weights, apache-2.0) with reasoning off for generation and medium for relabelling. `TEACHER_*` variables select the endpoint, falling back to `FALLBACK_*`. Of 1823 generated requests, 113 were duplicates, 254 were dropped for label disagreement (mostly act vs missing-required and look-alike tools), 12 for invalid labels, 9 as near-duplicates of scored scenarios. The top-up overshoots the quotas on act requests (every targeted group also holds contrasting act requests): alpha, shoes and sport have 71–80% act (quota 50–70%). The trainer is to sample each toolset down to its quota rather than weight classes. Alpha has 34 missing-required requests against a quota of 100: a request for a product without its id is usually served by `search_products`, so the relabel disagrees and the pair is dropped.
- The M4 live run hit HTTP 402 from the Jev account several times; it completed with `--jev-interval` pacing and `--jev-402-retry`, and every answer is cached.
- The ranking score is lexical: it finds no synonyms (Shoe Store files soccer shoes under `FOOTBALL`). The optional Jev `use_case_fit` score is not implemented yet.
- Sites run concurrently with `join_all` in one task rather than a `JoinSet`: the work is I/O-bound and borrowing the browser and router avoids `Arc`s.
- Prices in different currencies are never converted: with a budget in one currency, products priced in another are excluded with a reason.
